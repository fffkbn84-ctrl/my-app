# 返金の代わりに「次の予約に充てる」— 調査と設計案

> 2026-10-15 作成（ふうかさんの依頼）。前回の調査 `docs/ops/refund-loss-research-2026-10.md` の「1. クレジット方式」を、例外時の**標準の対応**にする案。
> 運営の手引きは `docs/ops/billing-and-refunds.md`。決まったら契約書と規約を直す（下の §5）。

---

## 1. ふうかさんの案（2026-10-15）

- 返金は基本しない。運営が認めたときは**次の予約の送客料に充てる**（スライド充当）
- 充てる前に相談所が Kinda を解約したら、そのときは返金する

## 2. 結論：やってよい。ただし3つ足す

いまの決まりは「原則返金なし・例外は運営の判断で返金」。充当はその例外の**出し方を変えるだけ**で、相談所にとって不利にはならない。
手数料 ¥218 も返金の日数もかからないので、Kinda にも相談所にも得がある。

そのうえで、このままだと困る点が3つある。

| # | 困る点 | 足すもの |
|---|---|---|
| 1 | 解約はしないが**予約が来ない相談所**だと、充当分がずっと使われずに残る。相談所から見ると「お金を返してもらえない」状態が続く | **期限を決める**：充当が決まってから**6か月**で使われなければ返金する |
| 2 | 何か月も後にカードへ返金すると、カードの解約・期限切れで**返金が失敗する**ことがある（Stripe は返金の期限を設けていないが、古いほど失敗しやすい） | 失敗したら**銀行振込で返す**と規約に書く。Stripe の `refund.failed` を受け取る |
| 3 | 充当を受けた後に、相談所が元の ¥5,500 にチャージバック（カード会社への申し立て）をすると**二重に戻る** | 申し立てが来たら、まだ使っていない充当は取り消す |

### なぜ6か月か

- 前払式支払手段（資金決済法）は「発行の日から6か月以内しか使えないもの」を対象から外している。充当はお金を受け取って発行する券ではないので、そもそも当たらない可能性が高い。それでも6か月で切っておけば、当たるかどうかを気にしなくてよくなる
- 期限が切れたら**消えるのではなく返金する**。これで「使われずに消えた」も起きない
- ⚠️ 前払式に当たるかは弁護士に1回確認する（調べた範囲では「返金の代わりの充当」をはっきり扱った資料は見つからなかった）

## 3. ほかに気をつけること

- **消費者契約法は関係ない**。相手は相談所（事業者）なので
- **規約の変更**：相談所に有利な変更なので、すでに契約している相談所の同意は要らない（民法の定型約款の変更・相手方の利益に適合する場合）。それでもメールでお知らせはする
- **税金**：充当した時点で「元の ¥5,500 の返還」として扱う。返還インボイスは1万円未満なので要らない（AGOGLIFE がインボイス登録している場合の話。手引き §4-2 の確認待ち）。帳簿のつけ方は税理士さんに1回確認
- **充当の単位**：「送客料1件分（¥5,500）」で持つ。部分的な金額は作らない（分かりやすさ優先）
- **どの場合に充当するか**：決まりはいまと同じ「やむを得ない事情があって運営が認めたとき」だけ。キャンセルやドタキャンを全部充当の対象にするかは、別の判断（下の §6-2）

## 4. 実装の要点（決まってから）

Stripe の顧客残高（Customer balance）は Billing／Invoicing を使う人向けで、Kinda は使っていない。充当は **Kinda の DB で持つ**。

1. 充当の記録：相談所ごとに「未使用の充当」を1件ずつ持つ表（発生日・期限・元の予約・使った予約・状態）。RLS 有効。作るのは運営だけ（admin か、Claude が SQL で）
2. 課金の手前で分岐：`/api/stripe/charge` で、その相談所に未使用の充当があれば**課金しない**で充当を使う
3. 課金しない場合も、いま Webhook（`payment_intent.succeeded`）で起きていることを同じように起こす：予約を支払い済みに・連絡先の開示・確定メール。**ここがいちばん抜けやすい**
4. 期限切れの返金：期限の近い充当を運営に知らせる（hello@kinda.jp へメール）。返金そのものは Stripe ダッシュボードでふうかさんが行う（Claude には返金の権限がない）
5. Webhook に `refund.failed` と `charge.dispute.created` を足す（後者は既存 TODO）
6. counselor 管理画面 /billing に「次の予約に充てる分：1件（期限 2027-04-15）」を表示する

条文のたたき台：
> 甲が前項ただし書により対応を認めた場合、甲は原則として、当該送客手数料を乙の次回以降の送客手数料1件分に充当する。充当が決まった日から6か月以内に充当されなかった場合、または乙が本契約を解約した場合は、甲は未充当の額を返金する。カードへの返金ができない場合は、乙が指定する銀行口座への振込により返金する（振込手数料は甲の負担とする）。

## 6. ふうかさんに決めてほしいこと

1. 期限は6か月でよいか（短くすると返金が増え、長くすると前払式の確認が要る）
2. 充当の対象は「運営が認めた例外」だけのままか。たとえば**利用者の無断不参加**も充当の対象にするか（相談所には嬉しいが、件数が増える）
3. 規約の書き換えを1社目の契約の前に済ませるか（推す。契約後に変えるとお知らせの手間が増える）

## 7. ふうかさんの決定と、返金の方法（2026-10-15）

- **期限は設けない。** 予約が入るまで充当を待つ。解約したときに残っていれば返金する
  - 期限なしにすると「6か月以内の適用除外」は使えない。ただ、充当は相談所がお金を払って買う券ではないので前払式に当たらない可能性が高い。
    仮に当たっても、自分のサービスにしか使えない「自家型」は**未使用残高が1,000万円を超えるまで届出が要らない**。Kinda の規模では当面届かない（弁護士確認は残す）
  - 相談所はいつでも解約すれば返してもらえるので、「お金が戻らない」状態にはならない
- **返金の方法：元のカードへ Stripe で返すのが原則。失敗したときだけ Kinda 名義の振込**（Claude 推し）

| | Stripe でカードへ返金 | Kinda 名義の銀行振込 |
|---|---|---|
| 元の課金とのつながり | Stripe 上で元の ¥5,500 に「返金済み」と残る | つながらない。別のお金の動きになる |
| チャージバック | 返金済みの課金は申し立てが通りにくい | **振込のあとに元の課金へ申し立てられると二重に戻る**。振込の記録で反論することになる |
| Kinda の記録 | Webhook で予約に `refunded_at` が自動で入る | 手で記録する |
| 手間 | ダッシュボードで1回押す | 相談所の口座を聞いて保管する（口座情報を持つことになる）・振込手数料 |
| 手数料 | 返金そのものは ¥0（元の ¥218 は戻らない） | 振込手数料が Kinda の負担 |
| 弱い点 | 何年も後だとカードが解約・期限切れで失敗しうる（失敗した額は Stripe 残高に戻る） | — |

- 期限なしの充当は年単位で残ることがあるので、カード返金の失敗は起きうる。**失敗したら振込で返す**を規約に入れておけば両方の良いところが取れる
- **相談所に選ばせるのは勧めない**。選んだ方法ごとに手順と記録が分かれ、振込を選ばれると上の二重払いの穴が開く。相談所から「振込がいい」と言われたときだけ、運営の判断で応じれば足りる
