## 2. 原因として確定したもの（2026-10-03 に本番を実測）

| 問題 | 影響 | 対応 |
|---|---|---|
| ルート `layout.tsx` に `canonical: "/"` があり、自前の canonical を持たない子ページ全部に継承されていた | `/kinda-act` `/shops` `/kinda-talk` `/contact` `/terms` `/privacy` `/tokushou` `/about/editorial-policy` `/about/transparency` と**全店の `/places/[id]`** が「トップの重複」扱い | canonical をトップの `page.tsx` に移し、該当ページに自己参照を付けた |
| `/places/[id]` にメタデータがない | 全店のタイトルが**トップと同じ** | `generateMetadata` を追加（店名・エリア・説明・OG） |
| 公開中の実在カウンセラー（Supabase）のメタデータが mock しか見ていない | タイトルが「**カウンセラーが見つかりません**」、canonical はトップ | Supabase からも引くように修正 |
| sitemap にお店の詳細ページがない | act の中身を Google に1件も送れていない | 掲載店（UUID の実在店）を送るようにした |
| act 一覧のカードが `<button>` | 詳細ページへのリンクを辿れない | 見た目と挙動はそのまま `<a href>` に変更 |

- 確認済み：`www` は kinda.jp へ 308 で転送／`my-app-rp9u.vercel.app` の canonical は kinda.jp を指す
- **残課題**：お店の URL が UUID。店名ベースの slug にする（DB に `slug` 列が必要。次の段階で行う）
- act 一覧は `useSearchParams` の Suspense によって、初回の HTML にカードが出ない。
  Google は JS を実行して読むので `<a href>` で辿れるが、slug 化のときに一覧のサーバー描画も検討する

## 4. Kinda glow：A 案（2026-10-03 ふうか決定）

- **店舗一覧としてはいったん閉じ、「会う前に自分を整える」を voices（コラム）のテーマとして育てる**（服・髪・前日の過ごし方など）
- 理由：掲載0店。行っていない店を載せると「行った人だけが書く」と相性が悪い
- 読まれ方を見てから、店舗化を判断する
- 実装（未着手）：トップの戸棚とナビから glow をどう扱うかを決めてから行う。`/kinda-glow` は0店の間 noindex（既に実装済み）

## 5. Kinda note：改修の方向（2026-10-03 ふうか了承）

いま「試しても広めるほどではない」「続けるほど面白くない」理由の仮説：
- 結果画面の主な導線が「カウンセラーに渡す」で、IG から来る読者の多くにとって使い道がない
- 最初の質問が「相談所に興味を持ったきっかけは？」。相談所をまだ考えていない人がここで離れる
  （CLAUDE.md §2「診断ページは中立語彙のみ」ともずれている）
- 一回答えたら完結し、もう一度やる理由がない
- 天気のカードは良い素材なのに、結果が「渡すメモ」として設計されている

方向：
1. 入口を「**いまの気持ちの天気**」にし、相談所の質問は後半の任意部分に移す
2. 結果は「**天気カード（シェアしたくなる面）＋カウンセラーに渡すメモ（折りたたみ）**」の2段構え
3. 「**先週の天気と比べる**」を足して、繰り返し使う理由にする（履歴の仕組みは既にある）
4. IG に「今週の天気」の定番の型を作り、note への入口にする
