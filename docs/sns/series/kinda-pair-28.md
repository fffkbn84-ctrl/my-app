# 連載シリーズ「ふたりの話題、ひとつずつ」— Kinda pair 28話題

- **目的**: Kinda の中身を具体的に紹介しながら、**フォローする理由**を作る
- **期間**: 28週（約半年）。1週1話題
- **ソース**: `src/lib/pair/topics.ts`（28話題の source of truth）
- **公開ページ**: `/kinda-pair` と `/kinda-pair/topics`（**28件すべて既に全文公開済み**）
- **作成**: 2026-09-10

---

## なぜ連載にするか（フォロワー0を破る設計）

2026-W27 レビューで分かったことは、単発では増えないということだった。
IGリールはリーチ100前後まで届くのにプロフ遷移0、Xは検索に載った投稿だけが動く。
**リーチは取れている。フォローの理由が無い。**

フォローは「良い投稿を見たから」ではなく「**次も来ると分かったから**」起きる。
だから必要なのは、良い単発ではなく**予測できる定点**である。

Kinda pair の28話題は、その定点にちょうど足りる。

- 在庫が**すでに28件ある**（半年ぶんネタ切れなし・毎週ゼロから考えない）
- 文言は `topics.ts` に確定済みで、**そのまま口に出せる聞き方（`ask`）が付いている**
- 28件はすでに `/kinda-pair/topics` で全文公開している。SNSで出しても**新たな開示はゼロ**

## 競合への開示について（判断済み・2026-09-10）

出す。理由は、隠して守れる資産を Kinda が持っていないため。

| 真似できる（1週間で） | 真似できない |
|---|---|
| UI・28話題のリスト・4層の分け方・コピー | 面談した人だけが書ける口コミの供給 |
| ページ構成 | 掲載相談所との契約 |
| 世界観の見た目 | 47都道府県の取材の蓄積 |
| | SEO順位・ドメイン権威 |
| | ふうか個人の声と、取材で築いた関係 |

左側は隠しても守れない。しかも `/kinda-pair/topics` は CLAUDE.md の不変則
「認証の後ろに隠さない。先に公開して権威を取るほうが強い」に従って**既に全件公開している**。
先に出して日付を刻むほうが、後から似たものが出たときに後発に見えるのは相手側になる。

### 出さない線（厳守）

- 送客料の単価（¥5,000）と契約条件 — 相談所との交渉材料
- 掲載パイプライン・営業リスト・契約前の相談所名
- 口コミ認証コードの発行の仕組みの詳細 — 悪用防止
- ユーザーの個票・登録数の内訳

## 並び順：層をローテーションする

28話題を第1層から順に出すと、最初の7週がすべて浅い話題になり、序盤のフックが弱い。
そこで **毎週 第1層→第2層→第3層→第4層 と回す**。

これは見せ方の都合であると同時に、**Kinda pair の思想そのもの**でもある。
仕様上「層は進捗ではなく深さ」と定めており、浅い順に消化していく見せ方は
「進んでいる／遅れている」という読みを生みやすい。4層を毎月ひと回りする並べ方は、
どの層も等しく置かれていることを、並べ方だけで示せる。

## X の型（毎週この4行）

```
1行目  顕在ワードを含む事実（「結婚相談所」「交際」「お見合い」のいずれかを必ず入れる）
2-3行目 観察と意見（「〜だと思う」で締める。ポエムにしない）
4行目  そのまま使える聞き方 ＝ topics.ts の ask をそのまま引用
```

- 本文に外部リンクを置かない（W27で確認済みの方針）
- セルフリプ1：`https://kinda.jp/kinda-pair/topics`（28件の聞き方が全部ある、と書く）

**4行目の `ask` をそのまま出すことが、この連載の中核。**

## Instagram の型（カルーセル5枚）

| 枚 | 内容 |
|---|---|
| 1 | **`ask` の文をそのまま大きく1枚** — これが1秒フック |
| 2 | なぜこの話題なのか（`about` の前半） |
| 3 | 答えに良し悪しがないこと（Kinda の非判定の姿勢） |
| 4 | この話題がどの層にあるか（ふれる／知る／重なる／描く の位置づけ） |
| 5 | 保存誘導＋「28件ぜんぶ公開しています」 |

W27 の改善（冒頭1秒に具体的な問いを大きく置く／「プロフィールのリンクから」CTAをやめて保存誘導に）を、
1枚目と5枚目に構造として埋め込んである。毎回の判断を不要にするための型。

### 4枚目の書き方（層）— 毎週この4行（2026-09-15 確定）

```
話題は4つの層に分かれています。
ふれる、知る、重なる、描く。
これは「<label>」の層です。
<lead>
```

`<label>` と `<lead>` は `src/lib/pair/topics.ts` の `PAIR_LAYERS` をそのまま使う
（ふれる＝好みや、日々のこと。／知る＝考え方や、人との付き合い方。／重なる＝暮らしが重なっていく部分。／描く＝この先のこと。）。
ページと文言が違うと、見に行ったときに別のものに見える。

> **4つの層名を毎回そろえて並べる。1つだけ書かない。**
> 初稿は「この話題は4つの層のうち『ふれる』にあります。」の3行だったが、
> **ふうかさんから「『ふれる』とだけ大きく出ると、婚活の文脈では性的な意味に読めるのでは」と指摘があり変更した。**
> 4つの動詞が並べば、身体の話ではなく**話題の深さの名前**だと説明せずに伝わる。
> 連載の語彙を毎週おさらいできるので、途中から見た人にも効く。
>
> **「話にふれる、という意味です」のような注釈は書かない。**
> 避けたい読みのほうを名指しすることになり、かえって意識させる。

> **「いちばん外側の」「いちばん深い」と書かない。** 位置の説明のつもりでも、浅い＝まだそこまで行っていない、と読める。
> 層は進捗ではなく深さ、が Kinda pair の不変則（CLAUDE.md §5）。

> **層名を単独で大きく置かない。** 1枚目のフックや画像内の見出しに `ふれる` だけを置くのも同じ理由で不可。

**火曜の連載はリールで出す。** カルーセルはフォロワー0の段階でリーチ0だったため

5枚の構成はそのまま5カットに置き換える。**文は1文字も変えない。**

| # | 秒 | 内容 | 版面 |
|---|---|---|---|
| 1 | 0〜3.5 | `ask` をそのまま（1秒フック） | モチーフ＋**58px** |
| 2 | 3.5〜7 | なぜこの話題なのか | モチーフ＋**48px** |
| 3 | 7〜10.5 | 答えに良し悪しがないこと | 別モチーフ＋48px |
| 4 | 10.5〜13.5 | 層の4行（下の「4枚目の書き方」） | 文字のみ・48px |
| 5 | 13.5〜16.5 | 保存誘導＋28件公開 | 固定モチーフ＋48px |

- **1カット目はズームなし。** 2カット目以降は 1.04 倍までゆっくり寄る
- カット間はクロスディゾルブ 0.4 秒
- 生成は **1:1**。`prep.py` が 9:16 に置き直す（モチーフ中心 y=680・サイズ340）
- 書き出しは `render-reel.js`（`hook`/`body`）＋ `build_reel.py`

> **土曜に同じ話題を出さない。** 旧設計では土曜の入口リールが火曜の話題を開く役だったが、
> 連載自体がリールになったため**近似重複**になる（2026-04-30 の IG オリジナリティ規定）。
> 土曜は別の内容（「言いにくい気持ち」）に差し替えた。

## 画像の型（2026-09-15 確定・カルーセル時代の版面。リール時は上の表を使う）

**週あたりの新規生成は1枚だけ。** 28週続ける前提でこの本数に抑えてある。

| 枚 | 画像 | 版面 |
|---|---|---|
| 1 | **その週の話題のモチーフ**（毎週新規生成） | モチーフ中心 y=420・サイズ300／質問 上端 y=690・**62px**・行間1.85・字間.06em |
| 2〜4 | **なし**（背景 `#F5EEE6` のみ） | 文字ブロックを**天地中央**／**44px**・行間2.05・字間.08em |
| 5 | **固定モチーフ**（一度作って28週使い回す） | モチーフ中心 y=420・サイズ300／本文 上端 y=710・44px。CTA の前に .7em の余白 |

- 画像サイズは全枚 **1080×1350（4:5）**、背景は厳密に `#F5EEE6`、書体 Shippori Mincho 400・`#2E2620`、絵文字なし
- 1行の上限：1枚目は**10字**、2〜5枚目は**16字**（グリッドの 3:4 クロップ幅 1012px に収まる範囲）
- **2〜4枚目に絵を置かない。** ここは読ませる枚で、絵があると読む速度が落ちる。
  また5枚すべてに絵を置くと28週で140枚になり、ひとり運用が続かない
- 1枚目と5枚目のモチーフは**同じ y=420**。連載の両端が揃い、スワイプの往復が落ち着く

### モチーフのプロンプト

共通テンプレートと作法は `docs/sns/series/iinikui-kimochi.md` §1・§2 と**同じものを使う**
（背景単色・クレイ・光は左上から・文字とロゴなし・小さく中央）。`【SCENE】` だけ毎週差し替える。

**1枚目の `【SCENE】` を考えるときの追加ルール**：この連載の1枚目は**二択の質問**であることが多い。
その場合は**2つのものを対等に並べる**（片方を手前や大きく置かない）。
片方が主役になると、3枚目の「どちらが良いという話ではありません」と絵が矛盾する。

実績（第1週 `l1-holiday`）：

```
A tiny clay sneaker and a tiny closed clay book, placed side by side with an
equal gap between them, both turned toward the viewer, neither one placed in
front of the other — the two are given exactly the same weight.
```

**5枚目の固定画像**（生成済み・28週使い回す）：

```
A small pile of tiny blank clay cards, gently fanned out — a few lying face-up
and a few still stacked face-down, as if a set of topics is being sorted
through. The cards are completely blank, with nothing written on them.
```

伏せ札と表札が混ざっていることが要点（＝話したこと／まだ話していないこと）。
1枚も伏せていない絵は不採用。カードに文字が読めたら再生成。

## プロフィール（両媒体・シリーズ開始時に更新する）

```
結婚相談所を、カウンセラーの口コミで選べるサイト
```

## 数える指標（1つだけ）

- **フォロワーの増減（週次）**。連載の目的はこれ一本なので、他は追わない
- 補助として X のプロフィールアクセス数（フォローの手前の行動）

インプレッションは連載の成否と関係が薄いので、判断材料にしない。
