KINDA VOICES — PUBLICATION KIT v1

掲載後キット

取材した記事を公開したあと、掲載カウンセラーに渡す配布物一式。
バッジ／埋め込みコード／告知文テンプレート3種／掲載完了メール文面／禁止事項。
このキットが存在する理由。
取材して記事を出すだけでは、被リンクは1本も増えない。増えるのは「掲載された側が、自分の意思で自分のサイトに載せたとき」だけ。 そのとき相手が困るのは「何を書けばいいか」「画像はどうするか」の2点。ここを先回りして潰すのがこのキットの唯一の仕事。
お願いをしない。相手が得をする材料を渡す。
PART A ── バッジと埋め込みコード

バッジのプレビュー

横長 260×72（記事下・フッター向け）／正方形 200×200（サイドバー向け・上図は160pxに縮小表示）

デザインの意図

  • Kinda のロゴ（クレイのワードマーク）を使う。このバッジは他社サイトに置かれる外部接点であり、見た人が後日 Instagram や note で Kinda に再会したときに結びつく必要がある。外部で使われているマークはロゴだけなので、ここでロゴ以外を使うと認知が分散する
  • 枠（カード）は装飾ではなく機能。濃色背景のサイトに置かれてもテキストが読める保証になる。枠を外すと文字が背景に溶ける
  • 評価語をひとつも入れない。「認定」「優良」「おすすめ」「No.1」は不使用。書いてあるのは「インタビュー掲載」という事実のみ（理由は PART D）
  • 日の出シンボルは使わない。日の出はサイト内部（KindaLoader / SectionDivider）のUIオーナメントであり、外部には露出していない。外部接点はロゴに統一する

PART B ── 告知文テンプレート（3種）
3種のうち、価値が桁違いに高いのは B-2。
サイドバーのバッジは1リンク。ブログ記事1本は「1ページまるごとが Kinda について語るページ」になる。 相手には3種すべて渡すが、こちらが本命として推すのは B-2。メールでもその順で並べる。

B-1 ／ 自社サイトの「お知らせ」用（短文・事務的）

ニュース欄・更新情報欄にそのまま貼れる長さ。2〜3行。

Kinda voices にインタビューが掲載されました 結婚相談所のカウンセラーを人単位で選べるプラットフォーム「Kinda」の連載企画 Kinda voices に、当相談所の{カウンセラー名}のインタビューが掲載されました。 この仕事を始めた理由と、面談で大事にしていることについてお話ししています。 ▶ 記事はこちら https://kinda.jp/voices/{slug}

B-2 ／ ブログ記事用（本命・400〜600字）

相手が自分の言葉を足せるよう、あえて余白を残した骨組みにしてある。全部埋まった完成文を渡すと「コピペした感」が出て相手が使いたがらない。

【タイトル案】 Kinda voices に取材していただきました ／ インタビューを受けて、あらためて言葉にしたこと 【本文】 このたび、結婚相談所のカウンセラーを人単位で選べるプラットフォーム「Kinda」の連載企画 Kinda voices で、インタビューをしていただきました。 （ここに、取材を受けての感想を2〜3行。「普段あまり言葉にしないことを聞かれた」「◯◯について話しました」など） 記事のなかでは、 ・この仕事を始めたきっかけ ・どんな方の相談に乗ってきたか ・面談のときに、これだけはしないと決めていること といったことをお話ししています。 （記事内で特に伝えたかった一節を、1〜2行引用してもよい） Kinda は、相談所単位ではなくカウンセラー個人単位で選べる、口コミ・レビュー型のプラットフォームです。 記事は下記からお読みいただけます。 ▶ Kinda voices｜{カウンセラー名} https://kinda.jp/voices/{slug}
「Kinda について」の説明文は、こちらが指定した一文をそのまま使ってもらう。
指定文：結婚相談所のカウンセラーを人単位で選べる、口コミ・レビュー型のプラットフォーム
理由：媒体側の説明が各社バラバラだと、AI検索（AEO）がKindaを何のサービスか特定できない。 同じ説明文が複数ドメインに存在することが、そのまま定義の強度になる。「中立」という語は使わない。

絵文字は相手の判断に任せる（Kinda側のサイト本文・記事は絵文字なしだが、他社のSNS運用に口を出さない）。

PART C ── 掲載完了メール（Resend / send.kinda.jp）

件名

本文

「ご紹介は任意です。掲載や今後の取り扱いには一切影響しません。」の一文は削らない。
これを外すと「掲載してやったのだから紹介しろ」という圧に読める。 さらに景表法上も、掲載可否と引き換えに紹介を要求した形になると、相手の投稿が「事業者の依頼による表示」＝ステマ規制の対象に近づく。 任意であることの明記が、相手の投稿を「自主的な感想」として守る。
キットは URL で渡す（添付しない）。
添付ファイルは開かれない・転送されない・スパム判定率が上がる。 /voices/{slug}/kit というページにして、そこにコード類を置く。 これなら相手が後日「あのコードどこだっけ」となったときに記事から辿れる。
なお、このキットページは noindex にする（検索結果に出す価値がなく、記事本体とカニバる）。
PART D ── やってはいけないこと

表記・法務

禁止理由代わりに
バッジに「認定」「優良」「おすすめ」「公認」 審査基準の実体がない優良性の表示＝景表法（優良誤認）のリスク。Kindaには審査制度がない 「インタビュー掲載」（事実のみ）
「No.1」「満足度◯%」 第三者調査の裏付けが必要。Kindaの規模では取得も維持も不可能 数値を掲げない
星評価・レーティングを含むバッジ Review 構造化データ禁止方針と矛盾。掲載側が自サイトで自社の星を表示するのは自己評価の表示になる 評価は Kinda 上にのみ置く
紹介を条件にした掲載・掲載順の優遇 ステマ規制（事業者の依頼による表示）。相手の投稿が広告表示義務の対象になり、相手に責任が及ぶ 「ご紹介は任意です」を明記
金銭を払って紹介記事を書いてもらう 同上。かつ被リンクとしても Google のリンクスパムポリシー違反 無償・任意を貫く

SEO

  • alt / アンカーテキストを商用キーワードにしない。全件同一の「Kinda voices インタビュー掲載」で固定する
  • 「相互リンクしましょう」と持ちかけない。Kinda voices の記事から相手のカウンセラー詳細ページへリンクするのは記事として自然だが、それを交換条件にした瞬間に相互リンクスキームになる
  • バッジのリンク先は記事URL（/voices/{slug}）に固定する。トップページに集めない。記事に集めたほうがインデックスされていないURLの発見に効く（現在の課題はまさにこれ）
  • Emma のバッジは発行しない。自社関係先からの被リンクは効かないうえ、利益相反の外形が悪い

透明性（記事側で必要な対応）

Kinda は予約成立時に相談所から手数料を受け取る。 取材記事の末尾に、関係性を1行で明示する必要がある。これがないと、記事全体が「広告であることを隠した表示」に見えうる。

記事末尾の固定文（案）：
この記事は Kinda 編集部による取材記事です。掲載にあたり金銭の授受はありません。Kinda はご予約が成立した際に、相談所から手数料を受け取ります。 → /about/transparency へリンク
PART E ── 運用フローとチェックリスト

公開当日の流れ

#やること担当
1記事を公開（MDX → デプロイ）Claude Code
2/voices/{slug}/kit が自動生成されていることを確認ふうか
3記事URLをX / SNSで共有（OGP画像が出るか目視）ふうか
4掲載完了メールを送信（Resend）ふうか
5Search Console でURL検査 → インデックス登録をリクエストふうか
6公開から2週間後、被リンクが付いたか確認（site: 検索 / 相手サイト巡回）ふうか

公開前チェックリスト

  • 記事末尾に透明性の1行がある（金銭授受なし／予約成立時に手数料）
  • バッジに評価語（認定・優良・おすすめ・No.1）が入っていない
  • 埋め込みコードのリンク先が記事URLになっている（トップページではない）
  • alt が全件共通の「Kinda voices インタビュー掲載」になっている
  • 掲載完了メールに「ご紹介は任意です」の一文がある
  • キットページが noindex になっている
  • 配信画像がPNG（SVG直リンクではない）
  • 記事のOGPが正しく生成されている（実際にSNSに貼って確認）

効果の測り方

1件あたりで見ない。10件公開した時点で、以下の3つを数える。

  • 被リンク獲得率＝バッジまたは告知記事を掲載してくれた件数 ÷ 公開件数。目標 40%（低く見えるが、無償・任意の依頼としては十分高い）
  • インデックス速度＝公開からインデックスされるまでの日数。被リンクが付いた記事とそうでない記事で比較する。ここが縮めば仮説が正しい
  • ドメイン全体のインデックス数＝site:kinda.jp の件数推移。voices が起点になってサイト全体の発見性が上がるかを見る
1〜2件で判断しない。今のKindaの課題は「被リンク欠如による発見の問題」であり、 これは母数が要る施策。10件を1セットとして評価する。
