# Kinda act 取材ログの分担（2026-09-27 改定）

> Notion「Kinda act 取材ログ」（`collection://2129912c-c31e-4a9b-bbe8-cf5292fdb788`）の項目を、
> **ふうかさんが書くもの／Claude が公式情報から埋めるもの／削除したもの** に分けた正。
> Notion 側の同内容は「Kinda act 取材ログ 記入ガイド」ページ冒頭。

## なぜ変えたか

- 1店の入力に時間がかかりすぎて、行った店がたまっているのに入力が進まなかった
- 41項目のうち、**公式サイトを見れば分かる項目**（住所・駅・予約・喫煙・価格 等）を
  ふうかさんが手で写していた。フィオレンティーナの「最寄駅・出口」は公式の文面そのまま
- 現地メモと項目欄に**同じ観察を2回書いていた**（PISOLA の現地メモは店の空気・沈黙の逃げ場と重複）
- **全店同じ値で、店を見分ける情報になっていない項目**があった（下の「削除」）

方針：**ふうかさんの時間は「行った人にしか書けないこと」に使う。** 感想の質は落とさない。

## ふうかさんが書く（体験）

| 種類 | 項目 |
|---|---|
| 最初に入れる | 店名／公式URL／訪問日／訪問時間帯／検証レベル |
| 主役（文章） | 現地メモ／最初の5分／先に着いたら待つ場所／迷いポイント（迷ったときだけ）／席配置＋席配置ラフ／沈黙の逃げ場／店の空気／店を出たあと |
| 1タップ（選択） | 入口の分かりやすさ／席の形／隣席との距離（目安mは任意）／店内の音量／客層／服装の許容幅／浮かなさ／回転圧／切り上げやすさ／会計動線 |

- **同じことを2か所に書かない。** 現地メモに書いたなら項目欄は空でよい。Claude が4章に振り分ける
- **文章に整えなくてよい。** 箇条書き・言いさしで十分。サイトの文面は Claude が書き、ふうかさんが確認する
- 項目欄は「現地で見ておくことのリスト」。全部埋まらなくても掲載できる（埋まった項目だけ出る）

## Claude が埋める（公式・予約サイトから）

住所／最寄駅・出口／徒歩分数／業態／予約／喫煙／個室・半個室／価格帯ドリンク1杯／
価格帯 食事1人／一行の観察（下書き→ふうかさん確認）／slug／二次情報確認日／公開状態

- **現地の観察が公式より優先。** 現地で違った（例：公式は予約可だが喫茶だけの予約は不可）ことは
  ふうかさんが現地メモに一言書く
- **公式に載っていない値は推測で埋めない。** 「要確認」として返す
- 価格は既存の不変則どおり **`価格帯 食事1人` はドリンク込み**で書く（TODO.md Kinda act 節）
- **`価格帯ドリンク1杯` は、ドリンクだけで席を使える店にだけ入れる**（2026-10-01 ふうかさん決定）。
  食事の注文が前提の店（コース・ビュッフェ・予約制の料理店など）は空欄にする。サイトの「ドリンク1杯」行は
  「お茶だけで会える店か」を示すためのもので、飲み物の単価を並べる欄ではない
  - レストランでも、カフェ利用（ドリンク・デザートだけ）ができる店は入れる（例：フィオレンティーナ、おだしもん）
  - 入れない例：明神下 神田川 本店（予約制の料理店）、くし葉（ビュッフェ）
- **サービス料がある店（ホテル等）は込みの額で書く**（実際に払う額。2026-09-27 決定）。内訳は括弧で添える
- 公式と記入が違うときは公式を採る（2026-09-27 ふうかさん了承。記入は「食事だけの最低額」になりやすい）
- 読み取った日を `二次情報確認日` に入れる。サイトの `last_reviewed_at` は引き続き **訪問日**

#### slug（2026-10-03 から URL に使う）

- `shops.slug` が詳細ページの URL になる（`https://kinda.jp/places/<slug>`）。**掲載時に必ず入れる**
- 形：英小文字・数字・ハイフン。**店名＋支店名（または館名）のローマ字**。例 `pisola-yokohama-mutsumicho`／`fiorentina-grand-hyatt-tokyo`
- **一度公開したら変えない**（変えると検索の評価を引き継ぎ直しになる）。旧 UUID の URL は自動で slug へ転送される
- 公開したら、ふうかさんに Search Console の URL 検査用に新しい URL を渡す

## 公式サイトの読み方

- 2026-09-27 に環境のネットワーク設定をフルにした。**`curl` で公式ページとメニュー PDF を取得して読む**
  （同じセッション内では WebFetch ツールだけ旧設定のまま遮断されていた。新しいセッションでは直るはず）
- ホテルの料金はページ本文ではなく**メニュー PDF** にあることが多い。PDF は Read で読める
- 検索結果の要約は古い値が混ざる。2026-09-27 にフレンチキッチンで検索要約（7,084円）と公式（5,500円・
  税込サービス料別）が食い違い、公式が正しかった。**値は必ず公式の一次ページから取る**

## 削除した項目（2026-09-27）

| 項目 | 理由 |
|---|---|
| テーブルの広さ | 7店すべて「書類を広げられる」。店を見分ける情報になっていない |
| 延長のしやすさ | 7店すべて「追加オーダーが自然にできる」。同上 |
| 系列店 | サイトのどこにも表示されていなかった |
| 観測した席 | 席配置と重複。値は各店の `席配置` 1行目「座った席：」に移してから削除した |

- テーブルが極端に小さい・追加注文しにくい、など**普通でないときだけ**現地メモに書く
- 掲載済み店の `act_observations.talk.tableSize` / `leave.extend` は DB に残っており、表示もそのまま。
  新しく載せる店ではこの2つが空になり、該当行が出ないだけ（ページは埋まった項目だけを描画する）
